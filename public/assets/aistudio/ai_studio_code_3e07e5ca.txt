# 1. ИСТОЧНИКИ ДАННЫХ И ТОЧНЫЙ ФОРМАТ ПАРСИНГА

1. **`https://info.dpem.mk.ua/off_graf.html`** (Плановый ГПВ + таблица адресов):
   * Внутри `<script>` объявлен массив `records = [ ... ];`.
   * Каждый объект записи:
     ```json
     {
       "date": "2026-11-22",
       "saved_at": "2026-11-22 15:31:34",
       "data": ["4", "4", "... ровно 576 строковых кодов ..."]
     }
     ```
   * **Математика 576 ячеек:** `12 подочередей × 48 получасовых слотов` (`00:00–24:00`).
     * Индекс подочереди: `qIndex = Math.floor(cellIndex / 48)` (`0`→`1-1`, `1`→`1-2`, `2`→`2-1`, `3`→`2-2`, `4`→`3-1`, `5`→`3-2`, `6`→`4-1`, `7`→`4-2`, `8`→`5-1`, `9`→`5-2`, `10`→`6-1`, `11`→`6-2`).
     * Индекс слота: `slot = cellIndex % 48` (`0` = `00:00–00:30`, …, `47` = `23:30–00:00`).
   * **Коды статусов ячеек:**
     * `'0'` → `on` (Електроенергія подається, `#22c55e`)
     * `'1'` → `switch_off` (Застосовується перемикання на відключення, до 30 мин, `#f97316`)
     * `'2'` → `off` (Відсутнє електропостачання, `#ef4444`)
     * `'3'` → `switch_on` (Застосовується перемикання на включення, до 30 мин, `#f97316`)
     * `'4'` → `possible` (Можливе відключення, `#eab308`)
   * **Таблицы адресов:** якоря `<div id="cherga-1">` … `<div id="cherga-12">` перед таблицами с 5 `<td>` в каждой строке данных:
     `[0] Населений пункт | [1] Підстанція | [2] № фідеру | [3] Тип перемикання (дист./місц.) | [4] Споживачі (ЧАСТКОВО: ...)`
2. **`https://info.dpem.mk.ua/off_o.html`** (Погодинні обмежувальні відключення — фактические окна):
   * Содержит метку `Інформація оновлена станом на: DD.MM.YYYY HH:MM:SS` и таблицу фактических отключений по подстанциям, фидерам, времени начала/конца и списку домов.
3. **`https://info.dpem.mk.ua/off_a.html`** (Аварійні відключення — источник для автоматических переносов `transfers`):
   * Содержит сообщения о временных переносах ТП/потребителей (например: «Споживачі ТП-19 перенесені до 6-ї черги, фідер 12»).
4. **`https://info.dpem.mk.ua/off_p.html`** (Планові відключення — ремонтные работы).

# 3. СТРУКТУРА ФАЙЛОВ ПРОЕКТА

Создай чистый модульный проект со следующей структурой:

```text
dpem-outage-map/
├── package.json                  # Зависимости (express, cheerio или пусто для Cloudflare)
├── wrangler.toml                 # Конфиг деплоя в Cloudflare Workers + Pages
├── backend/
│   ├── worker.js                 # Cloudflare Worker (CORS-прокси, парсер off_graf/off_o/off_a, кеш 120с, API /api/dpem)
│   ├── server.js                 # Альтернативный локальный Node.js-сервер (Express) для теста на ПК + раздачи статики
│   └── parser.js                 # Общий модуль парсинга HTML ДПЕМ (records + #cherga-1..12 + off_o + off_a)
├── data/
│   ├── street_aliases.json       # Словарь переименований и сокращений (Дружби Народів->Європейська, Курчатова->Мрій, Набер.->Набережна Енергетиків, Леніна->Незалежності и т.д.)
│   ├── dual_queue_overrides.json # База уточнений для домов с 2+ очередями: primary, secondary, dualType ("backup" | "split_entrances" | "split_lifts")
│   ├── google_extra_points.json  # Координаты объектов/корпусов из Google Maps, отсутствующих с адресом в OSM (20/145, 14/1/2/3, гуртожитки 1-8, ДКП-1, рынки)
```

# 4. ПРОЦЕССЫ И БИЗНЕС-ЛОГИКА (ОБЯЗАТЕЛЬНО РЕАЛИЗОВАТЬ)

### Процесс 1: Парсинг и нормализация адресов (`backend/parser.js`)
* Извлекать `records` из `off_graf.html`, преобразовывать 576 значений каждой даты в `{ [queue]: [48 статусов] }`.
* Разбирать таблицы `#cherga-1` .. `#cherga-12`, очищая HTML-теги, `&quot;`, `&nbsp;`.
* Раскрывать числовые диапазоны домов (`37-39` → `37, 38, 39`), НЕ ломая дробные и буквенные (`54-Б`, `20/145`, `14/1/2/3`, `3с/3`, `5/5`, `Гідробудівників –16`).
* Поддерживать улицы без номеров (МПЗ и сёла) как wildcard-правило на всю улицу.
* Автоматически находить все адреса, попавшие в **2 и более очереди** (`uniqueQueues.length > 1`), и выводить счётчик таких коллизий.

### Процесс 2: Разрешение двойных очередей (`frontend/js/resolver.js`)
В каждом многоквартирном доме возможно питание от 2 трансформаторов (`1Т`/`2Т`) или разных фидеров. Реализовать переключатель в UI и индивидуальное переопределение для каждого дома:
1. **`backup` (Основной + резервный):** учитывать только `primary` очередь; `secondary` показывать справочно в попапе; в попапе должна быть кнопка **«Сделать 2-ю очередь основной»** (меняет местами `primary` и `secondary`).
2. **`split_entrances` (Часть подъездов):** если одна очередь отключена, а вторая включена → красить здание фиолетовым (`#a855f7`) со статусом *«Частично: часть подъездов со светом»*. Если отключены обе → красный (`#ef4444`).
3. **`split_lifts` (Квартиры и лифты раздельно):** если отключена `primary` (квартиры), но включена `secondary` (лифты) → красить голубым (`#38bdf8`) со статусом *«Свет откл., лифты работают»*.

### Процесс 3: Перенос адресов между фидерами (`transfers`)
* Поддержка **ручного переноса** через форму на панели (выбор улицы, списка домов через запятую, целевой очереди и фидера) и быстрой кнопки **«Перенести на другой фидер»** прямо в попапе здания.
* Поддержка **автоматического переноса** из поля `transfers` ответа API (парсинг `off_a.html`).
* Перенесённые дома выделяются на карте пунктирным контуром (`dashArray: '5, 5'`), а в попапе указывается: *«Перенесён с [старая очередь/фидер]»*.

### Процесс 4: Опрос и Diff-перерисовка (`frontend/js/diffEngine.js`)
* Фоновый опрос API (настраиваемый интервал: 1 мин / 5 мин / вручную) + кнопка «Опрос сейчас».
* При каждом обновлении (ползунок времени, смена даты, фильтр, опрос API, перенос фидера) для каждого здания вычисляется строковый отпечаток `visualKey = color|opacity|dash|statusText|feeder`.
* Сравнивать `visualKey` с `lastVisualHash.get(buildingId)`:
  * Если совпадает — **НЕ вызывать `layer.setStyle()`**.
  * Если изменился — перекрасить только это здание и обновить `lastVisualHash`.
* В журнал изменений (Diff Log) выводить точное число: либо *«изменений нет (перерисовка пропущена)»*, либо *«перекрашено N из M зданий»*.

### Процесс 5: Карта OSM + Google Maps добор (`frontend/js/map.js`)
* Загружать через Overpass API (`https://overpass-api.de/api/interpreter`) в квадрате `47.805,31.135,47.845,31.205` все здания (`way["building"]["addr:housenumber"]`) и подстанции (`way["power"="substation"]`).
* Кешировать ответ OSM в `localStorage` / `IndexedDB` (чтобы не дёргать Overpass при каждом обновлении страницы, с кнопкой «Обновить карту OSM»).
* Подгружать слой `data/google_extra_points.json` для недостающих адресов и объектов (общежития 1–8, корпуса `20/145`, `14/1/2/3`, ДКП-1, рынки и т.д.).

### Процесс 6: Дополнительные функции UX (`frontend/js/ui.js`)
1. **Ползунок времени:** 48 шагов × 30 мин, автопрокрутка дня (Play/Pause), кнопка «Сейчас» (ставит текущий 30-мин слот).
2. **Выбор даты:** все даты из `records` (сегодня + архив + завтра, если уже выложено).
